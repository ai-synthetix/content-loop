# Исследование системы генерации и публикации контента

Дата: 2026-08-31

## Итог

Систему стоит строить как отдельный **content control plane** с обязательным человеческим утверждением публикации. FamilyOS должен быть потребителем и первым нестандартным адаптером, а не местом, где живёт вся оркестрация.

Рекомендуемая траектория:

1. Узкий пилот: `PattayaDom → FamilyOS + Telegram`.
2. Отдельный сервис рядом с FamilyOS, общая эксплуатационная инфраструктура.
3. Детерминированный workflow; LLM используется внутри ограниченных шагов.
4. Сначала draft/approve/publish и журнал публикаций, затем метрики и рефлексия.
5. Facebook подключается после стабилизации ядра и прохождения требований Meta.
6. Open source — после отделения секретов, моделей конкретных проектов и UI FamilyOS.
7. SaaS — только после подтверждения спроса вне собственных трёх проектов.
