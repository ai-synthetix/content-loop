Организация и эксплуатация

Как не превратить MVP в ещё один монолит и не размазать состояние по n8n.

📦 Репозиторий

Отдельный репозиторий content-loop. На пилоте допустим familyos/content-loop как отдельный deployable сервис.

  • /api — OpenAPI, JSON Schema контента
  • /internal/domain — state machine, entities
  • /internal/adapters/{telegram,familyos}
  • /web — Next.js review queue
  • /deploy/k8s — manifests, Helm values

🚀 Деплой на nebula (K3s)

Рядом с FamilyOS, общая эксплуатация, изолированные секреты.

  • Отдельная БД content_loop (Postgres), бэкап отдельно
  • Ingress: content-loop.beliberde.net + internal API
  • Secrets: TG_BOT_TOKEN, FAMILYOS_API_KEY — в K8s Secrets / Vault
  • Workers: publisher, collector — только они ходят наружу

🔒 Границы безопасности

  • Контентные workers не имеют доступа к БД FamilyOS
  • Публикация — только через publisher worker + audit log
  • Webhook Telegram проверяет secret, rate-limit + retry + DLQ
  • Каждая публикация привязана к immutable content_version

🧩 Роль n8n

  • Только расписания, cron-триггеры, временные интеграции
  • Не source of truth — состояние живёт в Content Loop DB + outbox
  • После MVP — оценить замену на собственный scheduler

Почему не n8n как ядро: логика расползается по workflow, нет транзакционного аудита публикаций.

Реестр и workflow — 1 неделя

Сервис, БД, state machine, outbox, очередь review

1 неделяGate: restart между draft и approval без потери состояния
▾

Сделать

6

Пилот — 2 недели

8–12 материалов, 2 темы, 2 формата, weekly reflection

2 неделиGate: решение — продолжать / упростить / остановить
▾

Объём

  • 8–12 материалов PattayaDom
  • Минимум 2 тематические группы, 2 формата Telegram
  • Review каждого материала, diff сохраняется
  • Одна weekly reflection после 1-й недели

Решение после

  • Продолжить ядро + добавить SoulArchitecture
  • Оставить как внутренний workflow
  • Остановить / упростить до n8n-набора
  • Только потом планировать Facebook

Метрики пилота — продолжать если

  • 100% публикаций имеют source version + approval
  • 0 дублей из-за retry · ≥95% jobs без ручного восстановления
  • ≥70% draft доходят до публикации · медианный edit distance <35%
  • Время на материал −30% · один замысел = 2 channel variants
  • Reflection изменила ≥2 последующих briefs

Остановить / упростить если

  • edit distance стабильно >50%
  • Журнал публикаций неполный, метрики не влияют на решения
  • Поддержка дороже ручного процесса
  • Источники / claims не проверяются reviewer
  • <70% черновиков доходят до публикации
